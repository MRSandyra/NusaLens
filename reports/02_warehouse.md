# Phase 2: Warehouse and SQL schema

Postgres 17.11 with pgvector 0.8.6 hosts a star-ish schema (dim_country, dim_indicator, fact_indicator, documents, chunks) plus observability tables, applied through 6 idempotent SQL migrations tracked in `schema_migrations`.

## Schema

| Table | Rows (loaded) | Purpose |
|---|---|---|
| dim_country | 16 | Indonesia + 15 comparators (ASEAN, China, Japan, South Korea, India, Australia, New Zealand) |
| dim_indicator | 53 | World Bank indicator metadata, deduped by code |
| fact_indicator | 38,216 | Indicator observations, PK (iso3, indicator_code, year) |
| documents | 15,000 | Wikipedia articles, source of chunks in Phase 3 |
| chunks | 41,297 | Chunked and embedded in Phase 3 |
| query_log, eval_run | 0 | Populated by later phases (agent execution, eval runs) |

Full column-level schema with live sample rows: `reports/raw/02_schema_card.json` (generated by `src/nusalens/warehouse/schema_card.py` against the running database, not written by hand).

## Migrations

6 SQL files in `src/nusalens/warehouse/migrations/`, applied in order by `runner.py`, tracked in `schema_migrations(version, applied_at)`.

| Version | File | Content |
|---|---|---|
| 1 | 001_init.sql | dim_country, dim_indicator, fact_indicator, dim_dataset, documents + btree indexes |
| 2 | 002_vector.sql | pgvector extension, chunks table with `vector(384)` column, HNSW index, tsvector column with GIN index |
| 3 | 003_observability.sql | query_log, eval_run, schema_migrations |
| 4 | 004_readonly_role.sql | `nusalens_ro` role: SELECT-only grants, 5s statement timeout, forced read-only transactions |
| 5 | 005_views.sql | `v_indicator_series` convenience view joining fact_indicator to both dimensions |
| 6 | 006_gin_documents.sql | GIN full-text index on `documents.text` (Indonesian text search config) |

Rerunning the migration runner against an already-migrated database prints "Migrations up to date" and applies nothing (verified: `reports/raw/02_schema_card.json` was generated after a second no-op run).

## Read-only role enforcement

The `nusalens_ro` role, intended for the Text-to-SQL agent's execution path (Phase 7), is verified to allow SELECT and reject writes and DDL:

| Operation | Result |
|---|---|
| `SELECT count(*) FROM fact_indicator` | succeeded, 38,216 rows |
| `DELETE FROM fact_indicator WHERE year = 2024` | blocked: `ReadOnlySqlTransaction cannot execute DELETE in a read-only transaction` |
| `CREATE TABLE evil (x int)` | blocked: `ReadOnlySqlTransaction cannot execute CREATE TABLE in a read-only transaction` |

Evidence: `reports/raw/02_warehouse_verify_wide.txt`.

## Sample query

`v_indicator_series` filtered to GDP per capita, 2023, ordered by value, returns the expected cross-country ranking (Singapore highest at ~$86.4k, Myanmar lowest of the 16 at ~$1.2k), confirming the join between fact_indicator, dim_country, and dim_indicator is correct on real loaded data. Full output in `reports/raw/02_warehouse_verify_wide.txt`.

## Loader idempotency

`src/nusalens/warehouse/seed.py` loads both gold Parquet files through a temp-table COPY followed by `INSERT ... ON CONFLICT DO UPDATE` (fact_indicator) or `ON CONFLICT DO NOTHING` (documents), so reruns after a data refresh do not fail on primary key collisions and do not duplicate rows.
